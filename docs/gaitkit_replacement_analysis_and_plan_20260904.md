# Gaitkit 步态参数模型对比与替换规划

## 1. 结论

Gaitkit 在空间参数的计算依据、时间采样一致性和代码可审计性上，明显优于当前部署的 MeTRAbs + VisionMD 参数链，适合作为下一版步态参数提取方案。现有证据尚不能证明它在真实测量精度上已经全面更高，因为当前对比只有两种视频方案间的差异，没有同步 Xsens、测力台或光学动作捕捉真值。

因此，替换决策分为两层：

- 工程与定义层面：建议采用 Gaitkit。
- 测量精度层面：先进行同视频影子对照和有真值验证，通过验收后再替换正式参数来源。

Gaitkit 没有更换 GaitTransformer 权重。它的主要改进来自 30 Hz 时钟校正、GVHMR 世界坐标骨架、事件时刻插值和沿人体真实行进方向计算空间参数，而不是一个精度更高的新事件神经网络。

## 2. 当前部署方案与 Gaitkit 对比

| 项目 | 当前部署方案 | Gaitkit | 判断 |
| --- | --- | --- | --- |
| 参数骨架 | MeTRAbs 17 关节相机坐标 | GVHMR 全局 SMPL-X 回归 H36M-17 + 足部点 | Gaitkit 更适合米制空间参数 |
| 时间输入 | 保留源视频约 15 FPS，120 帧，`pos_divider=2` | 先转 30 Hz CFR，60 帧，`pos_divider=None` | Gaitkit 与模型 30 Hz 训练时钟一致 |
| 步长 | 骨盆在相机深度 Z 轴上的位移 | 骨盆沿世界地面行进主轴的位移 | Gaitkit 不依赖相机朝向 |
| 步宽 | 相机 X 轴双踝距离 | 世界横向轴双踝投影距离 | Gaitkit 定义更合理 |
| 竖直参数 | 相机 Y 轴 | 重力对齐世界竖直轴 | Gaitkit 对相机俯仰更稳健 |
| 事件时刻 | 帧索引 | 秒级时间并允许亚帧插值 | Gaitkit 减少量化误差 |
| 动态稳定性 | 相机横轴、未平滑差分 | 世界横向轴、Savitzky-Golay 平滑速度、腿长倒立摆 | Gaitkit 物理方向更一致，仍是探索性指标 |
| 参数实现 | 单文件 28 项字典 | 注册表 + 分组纯函数 + 公式、单位和来源元数据 | Gaitkit 更易测试和审计 |
| 测试 | 当前平台有合同和映射测试 | 合成真值、预处理、管线及视频测试 | Gaitkit 数值单元测试更完整 |
| 页面产物 | MeTRAbs 骨架叠加视频 + GVHMR 网格视频 | 默认只输出数值，不渲染 | 替换时保留平台现有 GVHMR 展示产物 |

同一批 5 个行走窗口的已有对比显示：步时、跨步时间和摆动时间的平均相对差约为 4.62% 至 7.28%，主要节律基本一致；步长均值从 0.189 m 变为 0.444 m，步宽从 0.259 m 变为 0.128 m。空间差异很大，但方向符合“旧方法受相机轴影响、新方法沿世界行进轴测量”的预期。它支持 Gaitkit 的定义更合理，不等价于已经获得真实误差指标。

## 3. 源码核查结果

### 3.1 值得保留的设计

1. 视频片段先转换为真实 30 Hz 恒定帧率，再进入 GVHMR 和 GaitTransformer。
2. 事件检测输入逐帧中心化，只用于相位推理；原始世界坐标骨架继续用于空间参数，避免全局位移信息被误删。
3. 行进轴由骨盆水平轨迹 PCA/SVD 得到，空间参数不再绑定相机坐标轴。
4. 参数计算在事件秒级时刻插值关节位置，避免把亚帧事件粗暴取整。
5. 非世界坐标输入通过 `world_grounded` 门控，不输出伪装成米制结果的空间参数。
6. 28 项参数有集中注册表、单位、公式、证据层级和合成真值测试。

### 3.2 替换前必须处理的风险

1. **没有外部真值验证。** 合成测试证明公式按预期执行，不能证明单目视频在真人上的测量误差。
2. **输出合同不兼容。** 当前左右足清障高度分别输出；Gaitkit 合并为一个抬脚高度。Gaitkit 还把髋宽归一化稳定裕度拆成最小值和均值，字段总数虽然仍为 28，但语义不同。
3. **失败策略过严。** Gaitkit 当前要求至少 6 次 HS 且 28 项全部有限，否则整段失败；平台现有策略允许不可计算参数为空并进入质量复核。集成时应保留部分结果和质量原因。
4. **片段语义不足。** 默认运动分割器识别“有人且在运动”，不是严格的直线行走分类器；复杂背景、镜头移动和多人场景需要质量门控，必要时启用 YOLO。
5. **多片段与平台一条评估的关系未定义。** Gaitkit 会处理全部候选片段，平台目前围绕一个选定分析片段组织结果和视频。需要固定选择或聚合规则。
6. **质量字段缺口。** 当前页面依赖姿态有效率、全身可见率、插值比例和最大缺失间隔；Gaitkit 尚未直接输出同等字段。
7. **展示产物不同。** Gaitkit 为无渲染数值包，直接替换会丢失现有视频对比。应继续复用平台已有 GVHMR 原景和世界系渲染。
8. **运行环境需固定。** 包要求 Python 3.10 及以上；GVHMR 与 GaitTransformer 仍需独立 PyTorch/TensorFlow 环境。当前 `fall-risk-worker` 基础镜像为 Python 3.10，满足最低版本，但仍需在该隔离环境中补齐并锁定 SciPy、OpenCV 等依赖。
9. **许可证需复核。** GVHMR/SMPL-X 具有研究或非商业限制，GaitTransformer 为 GPL-3.0，正式部署前需确认分发方式。

## 4. 推荐替换架构

保持现有页面、Backend API 和两阶段跌倒风险逻辑不变，只替换 `fall-risk-worker` 内的步态参数来源：

```text
现有视频采集/上传
  -> Gaitkit 片段筛选与 30 Hz CFR
  -> GVHMR（继续产出当前页面需要的网格视频）
  -> Gaitkit 世界骨架 + GaitTransformer 事件
  -> Gaitkit 28 项参数
  -> CareShield 参数合同适配器
  -> 现有页面、KINECAL 和 GAITCLIP
```

适配器负责字段重命名、单位检查、可空值、质量原因和 `algorithm_version`，不让前端直接依赖 Gaitkit 的文件格式。历史 assessment 继续按旧合同读取，新结果记录 `gaitkit-2.0` 来源，禁止无版本覆盖。

## 5. 分阶段实施计划

### 阶段 A：基线冻结与合同设计

- 固定 10 至 20 段代表性视频，覆盖室内/室外、正面/斜向、15/25/30 FPS、正常与异常步态。
- 保存当前链逐样本事件、28 项参数、质量字段、耗时和失败原因。
- 确定新版 28 项对外字段。建议采用 Gaitkit 规范字段，同时提供旧字段只读兼容映射。
- 为单片段、多片段、事件不足和部分指标缺失定义明确策略。

验收：测试集清单、输入哈希、旧版输出和新合同文档可复现。

### 阶段 B：隔离接入

- 将 Gaitkit 作为 `fall-risk-worker` 内独立 adapter/vendor 模块接入，不把模型推理放入 Backend。
- 复用现有 GVHMR 权重与独立运行环境，避免同一视频重复跑两次 GVHMR。
- 新增 Gaitkit 输出到 `GaitParameterValue` 的映射和 `gait_algorithm_version`。
- 补齐质量字段；无法等价获得的字段设为 `null`，并新增清晰原因，不能伪造旧值。
- 保留现有页面 DOM 结构、卡片顺序、配色和视频区域，只替换数据来源与必要文案。

验收：单元测试、合同测试、历史 manifest 回读测试和前端构建通过。

### 阶段 C：影子运行与数值验证

- 同一视频同时运行旧链和 Gaitkit，新结果仅写审计文件，不改变用户页面结论。
- 比较 HS/TO 数量与时间差、参数差值、失败率、耗时和显存峰值。
- 对人工可标注的 HS/TO 抽样逐帧复核。
- 至少采集一批带同步参考的数据；优先验证步频、步时、跨步时间、步长、步速和步宽。

建议验收指标：事件时间 MAE、参数 MAE/MAPE/ICC/Bland-Altman、一致性失败率，并按拍摄方向和帧率分层报告。阈值应在看到参考设备误差和业务容忍度后冻结，不能由当前两方案差异反推。

### 阶段 D：灰度切换

- 增加配置开关 `legacy`、`gaitkit_shadow`、`gaitkit_primary`，默认先使用影子模式。
- 验证通过后将 Gaitkit 设为新 assessment 的主参数源；旧结果和回滚开关保留至少一个版本周期。
- 页面保持现有布局和视觉风格；历史记录明确显示算法版本，避免不同口径被误作纵向变化。

验收：端到端真实视频处理、部分失败降级、服务重启、历史记录和回滚演练全部通过。

### 阶段 E：清理与正式评估

- 稳定运行后再移除 MeTRAbs 参数计算依赖；若骨架叠加视频仍有展示价值，可独立保留或改用 GVHMR 关节渲染。
- 更新部署文档、模型卡、许可证清单和参数解释。
- 报告外部真值结果后，才能使用“精度提高”的正式表述；在此之前统一表述为“定义和时序配置更合理”。

## 6. 测试矩阵

| 层级 | 必测内容 |
| --- | --- |
| 单元 | 28 项合成真值、坐标旋转不变性、30 Hz 重采样、亚帧插值、空事件与异常值 |
| 合同 | 新旧字段映射、可空参数、算法版本、历史 manifest 回读 |
| 集成 | Gaitkit/GVHMR/GaitTransformer 三环境调用、缓存复用、超时和部分失败 |

## 7. 本轮建议

当前不直接删除旧链。下一步优先完成阶段 A 和 B 的最小版本：冻结对照视频、定义字段映射、增加 `gaitkit_shadow` adapter，并复用现有 GVHMR 结果。这样可以在不改变页面布局和用户可见结果的前提下，得到是否值得正式替换所需的真实证据。

### 已实施状态（2026-09-04）

阶段 B 的安全接入已完成：GaitKit 2.0 源码、许可证说明和上游测试已纳入 `fall-risk-worker/pipelines/gaitkit/`；Worker 新增 `legacy`、`gaitkit_shadow`、`gaitkit_primary` 三种模式，默认使用影子模式。新链复用现有 GVHMR `world_skeleton_3d.npz`，生成带算法版本、指标定义版本、30 Hz 时钟、事件计数和原生 28 项参数的独立结果文件。主模式下字段不伪装成旧版左右足参数；若执行失败，则保留旧参数并记录 fallback。

一条已有历史世界骨架已完成离线实跑：输入 458 帧、30 Hz，解码出 17 次 HS、17 次 TO，28 项参数全部可计算。旧链与新链在该样本上的步频分别为 30.0 和约 66.4 steps/min，步时分别为 2.0 和约 0.904 s，说明旧版时间口径确实可能造成显著偏差；该结果没有同步人工事件或测量设备真值，仍不能作为新方案准确率结论。

当前仍保留 MeTRAbs，用于既有片段选择、姿态可见性质量门控和旧版参数回退。下一实施阶段需要先完成多样本影子对照与事件标注，再将片段选择和质量字段迁移到 GaitKit，最后才能删除重复的 MeTRAbs 参数计算。

## 8. 审计证据与验证边界

当前部署链的直接依据包括：

- `fall-risk-worker/pipelines/visionmd/run_rgb_to_28.py`：MeTRAbs、源视频时钟、`pos_divider=2`、120 帧事件窗口。
- `fall-risk-worker/pipelines/visionmd/visionmd_gait_backend/app/analysis/gait_parameters_28.py`：相机坐标下的 28 项参数公式。
- `fall-risk-worker/pipelines/gvhmr/run_gvhmr_world.py`：现有 30 Hz GVHMR、世界骨架、SMPL-X 及展示视频产物。
- `fall-risk-worker/app/services/assessment_service.py`：当前评估编排、质量控制、KINECAL 与运动功能模型调用关系。

新方案依据来自压缩包内的 `gaitkit/workflow.py`、`gaitkit/pipeline.py`、`gaitkit/preprocess/`、`gaitkit/events/visionmd.py`、`gaitkit/metrics/`、`gaitkit/io/gvhmr.py` 和 `tests/`，以及《两种步态参数方案结果与方法对比分析》。压缩包 SHA-256 为 `bf13abbcbec6ac056d7b1d08ed7542221a5c6c9b4b26f35cab05ddd2d6b7b37e`，不含 `.pt`、`.pth`、`.ckpt`、`.onnx` 等权重文件；它是管线源码，不是一个自带完整模型权重的独立“新模型”。源码可通过 Python 编译检查，随包共发现 27 个测试函数；本轮没有安装新依赖，现有项目虚拟环境因缺少 `scipy` 和 `cv2` 无法收集该包测试。因此测试是否全部通过仍标记为【待接入环境验证】，不作为精度证据。
