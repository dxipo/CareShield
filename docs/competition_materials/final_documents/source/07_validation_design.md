# 文档说明

本文档对应建议提交材料“07_验证设计”，用于评委在不接触 Secret、不要求老人执行危险动作、不改变系统数据的条件下，验证智安护居（CareShield）V1.0 的设备接入、实时媒体、算法链、风险展示和故障语义。验证基线为 Git 标签 `v1.0.0`、提交 `e8e474c`。

验证分为“工程可运行性、真实链路真实性、算法功能、异常与安全、统计性能”五层。前四层可在当前系统中按步骤执行；统计性能需要固定数据集和原始标签，不能以现场单次演示代替。所有截图必须遮蔽 AppKey、AppSecret、AccessToken、完整设备序列号、播放地址、人物身份和家庭敏感文本。

# 1 验证原则

## 1.1 证据分级

| 证据等级 | 定义 | 可支持的结论 |
|---|---|---|
| A | 固定 commit、命令输出、API JSON、测试原始文件可相互复核 | 系统实现和工程测试结果 |
| B | 真实设备页面、现场录屏、人工动作与页面同步 | 真实业务链能运行 |
| C | 单元测试、synthetic fixture、Mock 第三方网络 | 代码分支和契约正确性 |
| D | 方案说明或待开通接口 | 规划能力，不能写成已实现 |

一项功能要写成“真实设备已验证”，至少需要 A+B；模型 Accuracy、Recall 等指标必须有固定测试集、真实标签、逐样本输出和可复算脚本。播放器 firstFrame、HTTP 200 或 ffprobe 成功只证明特定技术环节，不能单独证明画面是当前摄像机内容。

## 1.2 安全与伦理

真人测试需获得书面授权，明确用途、保存期限、展示范围和删除方式。实时跌倒验证优先使用健康成年人在软垫环境中的安全模拟或合法测试视频，不要求老人执行跌倒。诈骗验证使用虚构账号、验证码和身份，不播放真实家庭敏感对话。运动功能评估不得以页面分级替代临床诊断。

验证者只使用脱敏页面和安全状态接口；不打开 `.env`，不复制播放地址，不查看完整设备序列号，不导出原始家庭音频。停止系统时不使用 `docker compose down -v`。

# 4 详细验证步骤

## 4.1 V01 全栈部署与健康

**验证目标。** 证明提交源码在目标主机可以构建并启动完整服务，而不是只展示开发截图。

**前置条件。** `.env` 和模型挂载已按部署文档配置，Docker daemon 和 GPU runtime 可用。

**操作。** 执行 `docker compose up -d --build`，随后执行 `docker compose ps`、`curl -f http://localhost:8000/api/health` 和 `curl -f http://localhost:5173/api/health`。

**预期结果。** 12 个服务 Up；10 个带健康检查的服务 healthy；两个 health 地址均返回 `status=ok, service=backend`。

**通过标准与证据。** 保存包含时间、commit 和完整服务列表的终端截图；任一核心服务反复 restarting 判定不通过。

## 4.2 V02 配置与 Secret 安全

**验证目标。** 证明提交包不包含本机凭据和临时媒体资源。

**操作。** 执行 `git check-ignore -v .env`、`git status --ignored --short .env`，并对受版本控制文件搜索 password、secret、token、appkey、appsecret、authorization、api_key、private_key。搜索程序只输出文件和命中类型，不打印实际值。

**预期结果。** `.env` 被 `.gitignore` 命中；`.env.example` 只有 `your_app_key`、`your_app_secret`、`change-me` 等占位符；源码、测试和文档不包含真实 AccessToken、完整播放地址或 SSH 私钥。

**通过标准与证据。** 保存 ignore 规则和脱敏扫描摘要。发现真实凭据立即停止交付并轮换相关凭据。

## 4.3 V03 EZVIZ 设备接入

**验证目标。** 证明系统通过萤石开放平台查询真实设备，而非 Mock 列表。

**操作。** 打开 `/devices`，同时调用 `/api/integrations/ezviz/status` 和 `/api/devices`。在萤石控制台确认同一账号下设备在线。

**预期结果。** status 返回 configured=true、reachable=true；CareShield 显示 1 台 EZVIZ H6c、型号 CS-H6c-V200-8H8WFL、Online，序列号脱敏。

**通过标准与证据。** CareShield 与萤石控制台设备型号和状态一致。截图不展示 AppSecret、AccessToken 和完整序列号。

## 4.4 V04 浏览器低延迟实时画面与音频

**验证目标。** 证明综合首页播放的是当前 H6c 实时画面，而不是测试视频或平台错误提示流。

**输入。** 在摄像机前移动具有明显颜色和位置特征的物体，并发出可辨识声音。

**操作。** 打开 `/dashboard`，等待官方播放器 LIVE；记录摄像机前动作和网页画面的同屏视频；切换全屏后按 Esc 退出，再测试控制栏、声音和刷新。

**预期结果。** 页面画面随现场动作变化，比例保持正常；全屏退出后控制按钮可见；声音可通过官方控件播放；刷新会销毁旧实例并获取新会话。

**通过标准与证据。** 同屏录制能确认真实内容。仅 firstFrame 或 media request 成功不判定通过。精确延迟需使用统一时钟逐帧测量，不凭主观“几乎无延迟”填写数值。

## 4.5 V05 服务端媒体与多消费者

**验证目标。** 证明 Linux 算法侧能解码真实媒体，并由单一中继同时服务视频与音频 Worker。

**操作。** 调用 media-info 获取安全元数据，查看 media-relay、ai-worker、fraud-worker health；连续观察两 Worker 的 stream/audio status。

**预期结果。** 视频为 HEVC/H.265 Main、1920×1080、约15FPS、yuv420p；音频存在，为 AAC LC、16kHz、mono；relay healthy，实时跌倒 stream connected，诈骗 audio connected。

**通过标准与证据。** 元数据与 H6c 会话一致，响应不含 URL。两个 Worker 同时工作时不需要分别向前端暴露媒体地址。

## 4.6 V06 人物、姿态与追踪

**验证目标。** 验证人物存在检测、COCO17 骨架和轻量 ID 关联在日常动作中的行为。

**输入。** 一人进入、走动、短时被家具遮挡、侧身、弯腰和安全躺下；多人测试另行登记。

**操作。** 打开 `/fall-detection`，观察人物框、骨架、person_count、keypoint confidence、track ID 和 warming_up。离开画面后继续观察状态。

**预期结果。** 站立和走动时人物框与骨架跟随；短时遮挡后尽量保持同一 ID；横卧姿态关键点不足时人物框仍可存在；无人、低置信或 warming_up 不显示 Normal。

**通过标准与证据。** 保存连续录屏而非单帧截图。多框、ID 切换、横卧漏检应作为误差样例登记，不删除失败片段。

## 4.7 V07 实时跌倒、告警与人工确认

**验证目标。** 验证 STGCN-Extend 真实结果、状态机和告警后处理。

**输入。** 合法跌倒测试视频在摄像机前播放，或健康成年人在软垫和保护人员条件下安全模拟；禁止老人危险测试。

**操作。** 从人物稳定出现开始录屏，观察 warming_up、suspected_fall、fallen 和 recovering；出现红色告警后等待至少 15 秒并点击人工确认；恢复直立后继续观察。

**预期结果。** 结果 `task=fall_detection`、`simulated=false`；可靠骨架积累后产生 fall_score；达到 0.65 进入 FALLEN，红色条幅和人工确认控件出现；未确认告警至少保留 15 秒；确认后关闭本次展示；恢复需连续低分窗口。

**通过标准与证据。** 页面、WebSocket 结果和事件时间一致。只出现疑似跌倒不能记作 fallen 成功，应保留为漏检/阈值样例。

## 4.8 V08 摄像机采集跌倒风险评估

**验证目标。** 验证点击时刻采集、批处理进度和历史产物。

**输入。** 固定机位、全身与双脚持续可见的直线自然行走，填写姓名、性别、年龄和身高。姓名使用测试编号，不输入身份证等信息。

**操作。** 在 `/fall-risk` 选择摄像机采集，提交后观察进度；完成后查看输入视频、人体网格、8 项重点参数、全部参数、跌倒风险与运动功能结果；刷新页面并从历史记录重新打开。

**预期结果。** 采集时间从按钮触发开始；源视频无绿色参考帧；任务依次完成媒体校验、步态、GVHMR 和模型分析；历史记录保留受试者字段和产物。参数不足时字段为 null 并保留质量依据，不补随机数。

**通过标准与证据。** 输入视频与测试动作对应，刷新后可回看。源视频、SMPL-X 和 JSON 的 assessment_id 一致。

## 4.9 V09 上传视频跌倒风险评估

**验证目标。** 验证已录制 MP4 与摄像机采集复用同一算法管线。

**输入。** 8–60 秒、全身可见、已授权 MP4；记录文件 SHA-256。

**操作。** 选择“导入视频”，填写受试者信息并上传；记录任务 ID、进度、完成时间和产物；切换其他历史记录后再返回。

**预期结果。** SOURCE VIDEO 显示上传文件；同一任务产生参数、SMPL-X、KINECAL 与 MotionCLIP 结果；历史切换时源视频不出现黑框，左右视频与结果均跟随任务。

**通过标准与证据。** 任务 ID、输入 SHA-256、结果 JSON 和页面截图形成一一对应关系。无可用人体时任务明确失败，不生成虚假风险等级。

## 4.10 V10 KINECAL 跌倒风险分级

**验证目标。** 验证世界系骨架进入独立 KINECAL Worker 并生成研究三分类。

**操作。** 选择已完成 GVHMR 的评估，检查 KINECAL 状态和结果合同。

**预期结果。** 输入为 H36M-17、120 帧、`[N,3,120,17,1]`；输出 NF/FHs/FHm 三类分数、预测标签、low/medium/high 分级和 review 标记。结果不称未来跌倒概率。

**通过标准与证据。** 页面结果与 artifact JSON 一致，Worker 不接触 EZVIZ Secret、视频地址和前端。分类准确率必须另按第 6 章执行，现场单段结果不作准确率证明。

## 4.11 V11 MotionCLIP 运动功能评估

**验证目标。** 验证 SMPL-X 动作窗口到健康参考距离与运动概念解释的链路。

**操作。** 对同一已完成评估检查 MotionCLIP 输入、checkpoint profile、输出和解释生成元数据。

**预期结果。** 输入窗口为 `[B,25,6,60]`；输出健康参考距离、低/中/高参考偏离区间和 8 项运动概念；Qwen 只组织已有数据为自然语言，不修改模型分级。

**通过标准与证据。** 数值、概念和解释可追溯到同一 assessment。页面名称使用“基于 MotionCLIP 的神经退行性疾病相关运动功能评估技术”，不展示疾病诊断结论。

## 4.12 V12 诈骗识别与告警确认

**验证目标。** 验证 H6c 音频、SenseVoiceSmall、规则/上下文/Qwen 和告警状态。

**输入。** 一组正常对话与一组虚构诈骗话术，例如要求向“安全账户”转账并提供验证码；不使用真实身份和账号。

**操作。** 打开 `/fraud-risk`，先播放正常语音，后播放高风险语音；观察转写、`llm_used`、证据、风险状态和事件；告警后点击人工处理。

**预期结果。** Audio connected、SenseVoice ready、Qwen ready；正常语音不形成 warning/critical；高风险组合达到告警时显示红色条幅和处理按钮；发布文本脱敏限长；人工确认只处理当前生命周期。

**通过标准与证据。** 页面、WebSocket 与事件记录一致，原始音频未写入数据目录和日志。语音播报接口默认关闭，不把预留能力列为成功项。

## 4.13 V13 Redis 与 WebSocket

**验证目标。** 证明实时结果从 Worker 到浏览器使用统一链路，刷新后状态可恢复。

**操作。** 打开 `/algorithms` 和一个业务页面；触发明确的开发 pipeline test，再触发一条真实业务结果；断开浏览器网络后恢复。

**预期结果。** pipeline test 带 `task=pipeline_test, simulated=true`，只出现在开发诊断，不更新 Dashboard 风险和事件中心；真实结果写入 Redis latest 并通过 `/ws/realtime` 到页面；断线后客户端退避重连并重新读取快照。

**通过标准与证据。** 同一 result_id 在 Backend 接收、Redis/接口和浏览器中一致。一个浏览器只维护统一 realtime channel。

## 4.14 V14 服务异常与恢复

**验证目标。** 验证故障不会被错误呈现为安全状态，且基础 Backend 不因单个模型故障崩溃。

**操作。** 在维护窗口内依次停止 ai-worker、fraud-worker 或断开 H6c 网络；每次只改变一个条件，记录页面和 API；恢复服务后观察自动重连。该操作会影响运行系统，必须由现场负责人执行。

**预期结果。** 对应业务页显示 unavailable/offline/reconnecting，Dashboard 不把失败当作 0 风险或正常；`GET /api/health` 保持 ok；服务恢复并产生新 heartbeat 后重新显示在线。

**通过标准与证据。** 故障与恢复时间、页面状态和 Worker heartbeat 对应。未经授权不执行容器停止操作。

## 4.15 V15 风险事件

**验证目标。** 验证事件中心记录真实跌倒和诈骗告警，且不混入普通状态或模拟数据。

**操作。** 分别完成 V07 和 V12，打开 `/events`，检查事件类型、时间、风险等级和分页；刷新页面。

**预期结果。** 跌倒与诈骗使用不同图标；同日趋势分别显示数量；每页 10 条并可翻页；`simulated=false` 的告警生命周期进入记录，pipeline_test 和 normal 不进入。

**通过标准与证据。** 事件 result_id 与算法输出对应。Redis 有界记录不是正式长期数据库，重建数据卷会丢失。

# 5 验证数据与记录格式

每次验证建立唯一 `validation_run_id`，至少记录日期、代码 commit、Compose 镜像摘要、设备脱敏 ID、输入文件 SHA-256、操作者、开始/结束时间、预期、实际结果、通过/失败、截图或日志路径。算法样本另外记录受试者匿名编号、场景、标签来源和授权编号。

| 字段 | 示例形式 | 隐私要求 |
|---|---|---|
| validation_run_id | `VAL-20260904-001` | 可公开 |
| git_commit | 40 位 hash | 可公开 |
| device_id | hash 或末四位 | 禁止完整序列号 |
| input_sha256 | 64 位摘要 | 可公开 |
| participant_id | `P001` | 不写姓名 |
| expected / actual | 结构化状态 | 不含 Secret |
| evidence_path | 脱敏截图/JSON | 访问受控 |
| consent_id | 授权记录编号 | 授权原件单独保存 |

# 6 统计性能验证设计

## 6.1 跌倒检测

测试按受试者隔离，覆盖跌倒与高相似日常动作。事件级 TP 定义为标注跌倒窗口内首次出现 FALLEN；漏报为窗口内未出现 FALLEN；非跌倒动作或正常监护时段出现 FALLEN 记为 FP。报告 precision、recall、F1、每小时误报、漏报、首次告警延迟 P50/P95 和连续运行可用率。阈值调整只能使用验证集，测试集只执行一次冻结评估。

## 6.2 跌倒风险与运动功能

风险分级使用受试者级独立划分，保存 NF/FHs/FHm 三分类逐样本分数、混淆矩阵、balanced accuracy、macro F1 和每类 recall。步态参数与可追溯参考标注比较 HS/TO 时间误差、步数、步频、步时和步长误差。MotionCLIP 单独评价健康参考距离与运动功能量表或标注的相关性，不把相关性写成疾病诊断准确率。

## 6.3 诈骗识别

测试集按说话人隔离，同时包含诈骗与语义相近的正常对话。先计算 SenseVoice CER/WER，再计算语句级和会话级 precision、recall、F1、每小时误报、漏报与响应延迟 P50/P95。规则 only 与规则+Qwen 分别运行，保留逐样本差异，避免只报告最好配置。

# 7 证据归档与通过判定

最终证据包按“运行环境、设备与平台、媒体、跌倒检测、跌倒风险、诈骗、实时链、异常恢复、算法统计”分类。每类包含固定 commit、脱敏原始输出、页面截图、必要录屏和结果摘要。截图只作为可视证据，测试结论必须能回到 JSON、日志或逐样本表。

整体验证通过需要 V01–V05、V13 和核心选题对应业务用例通过；统计性能章节只有在原始数据齐全时才能填写数值。V14 涉及中断运行服务，可在演示前的维护窗口单独执行。任何隐私违规、凭据泄漏、危险老人测试或模型名称与真实实现不一致均判为材料不合格。

# 8 现场演示建议顺序

现场以连续录屏呈现：先展示 commit 和 Compose 状态，再展示 H6c 在线与综合首页真实画面；随后完成正常走动的人物/姿态、一次安全跌倒告警与确认；导入一段授权行走视频并从历史记录展示源视频、网格、参数和双模型结果；最后播放正常与诈骗语音对照，展示 ASR、风险、告警和事件中心。系统页用于证明 Backend、Redis、Worker 和 WebSocket 状态。

长时批处理可提前准备固定 assessment_id，但必须同时保留原始输入 hash、生成时间和运行日志，不能用剪辑掩盖处理步骤。出现失败时展示明确 unavailable 和恢复过程比替换为静态成功页面更符合验证原则。
