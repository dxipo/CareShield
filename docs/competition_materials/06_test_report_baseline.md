## 1. 测试目的与环境

目标是证明真实 H6c 设备、媒体、算法服务和页面之间能够连通，并划定算法有效性尚未覆盖的范围。既有验收环境为 Ubuntu、RTX 4090、Docker Compose、EZVIZ CS-H6c；软件版本见依赖文件。具体驱动、Compose版本、GPU显存占用和每次测试Git hash未形成统一归档，【待补测】。

## 3. 算法结果

实时跌倒模型的 88/88 只属于 checkpoint/preprocessing compatibility test，不能写入“系统准确率”。KINECAL 74% 与高风险 recall 0/7暴露验证集限制，正式报告只有在原始逐样本输出回收后才能引用。MotionCLIP macro-F1 0.505334属于训练分区阈值选择。诈骗模块没有标注测试集指标。因此当前可正式陈述的是“链路和模型实际运行”，不能陈述“检测准确率达到某值”。

## 4. 异常与风险

既有调试中出现过 HLS 返回H.264错误提示视频、HEVC转封装绿色块、人物横卧时姿态丢失、风险视频有效步数不足、Worker心跳聚合误显示Not Installed和诈骗ASR同音误识别。当前代码分别加入H.265显式参数、共享中继HEVC解码与低延迟H.264规范化、独立人物框/裁剪旋转pose fallback、连续段质量门、聚合capability和同音词共现约束。这些是工程修复事实，不等于问题已在统计意义上消除。

## 5. 测试结论

系统已具备从真实设备到多Worker再到页面的可运行工程基线。媒体和服务通信有明确证据；三类算法的泛化、临床相关性、长期可靠性和端到端时延缺少规范实验，应标为【待补测】。答辩前必须以固定Git hash重跑全套测试并导出结果。
